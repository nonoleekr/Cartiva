3. Keep `PROJECT_MEMORY.md` compact and current; append `DEVELOPMENT_LOG.md`. Clearly separate implemented work from planned milestones.
4. Before a milestone handoff, preview and apply the sync, then verify:

```powershell

python scripts/sync_obsidian.py
python scripts/sync_obsidian.py --verify
```

The script uses only Python standard library. It adds metadata/provenance to copies, preserves source Markdown bodies, includes the safe environment example and previously recorded screenshots, links the vault hub from Home, and logs the update in Maintenance Log. It records source and target SHA-256 hashes. It does not run application tests or imply Obsidian's UI was visually checked.

After each significant verified development part, finish this note/sync loop and create a descriptive local Git commit containing only that part's intended changes and supporting documentation. Include this commit action explicitly in the development plan. No push or retrospective bulk commit is implied by this workflow.

## Conflicts and safety

- Existing managed files changed since the last sync cause a refusal, not overwrite. Read and merge user edits into the correct repository document or personal note, then explicitly reconcile the prior sync record before retrying. Never bypass this protection merely to complete a sync.
- Existing unrecognized files at a managed destination also cause a refusal. Unknown neighboring files are retained.
- Before altering Home/Maintenance Log, make external backups in the repository's ignored `.local/obsidian-backups` directory.
- No vault settings, plugins, drawings or unrelated topics are altered. No `.env`, session/token/cache data, DB dumps, node_modules or builds are exported. `.env.example` is the sole allowlisted environment sample.
- If a source is removed later, the script leaves its old vault note alone; review removals explicitly to preserve user content.
- If the sandbox requires escalation for the vault path, use the existing user authorization for this sync and report any rejection accurately. Do not claim the vault is updated when only repository documents were prepared.
